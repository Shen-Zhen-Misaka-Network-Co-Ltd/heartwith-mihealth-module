# 2026-09-08 资源使用优化

范围：分仓库 LSP 模块。不改 uploader SDK API，不提交或安装。

## 已实施

1. `HeartwithUploader` 只缓存上一种来源对应的上传字符串。同源心率复用字符串，切换来源时重新规范化；空值及空白输入仍使用原默认值。缓存容量固定，不引入随包增长的 Map。
2. 定时同步、睡眠 poll、心率 watchdog 在重新设置同一 PendingIntent 时，不再先执行一次 `AlarmManager.cancel`。Android 原生会替换同一 PendingIntent 的旧闹钟，减少一次跨进程调用；关闭功能时的显式取消保留。闹钟类型、间隔、窗口和 generation 校验均未修改。
3. debug 文件日志复用一个 BufferedWriter，每行立即 flush，不再每行 open/close 文件和分配缓冲区。跨天关闭旧写入器；热重载关闭文件并拒绝旧日志器的迟到写入；写入异常释放写入器，后续行可以重新打开。七天保留规则、日志内容、逐行可见性不变，没有新增日志定时器或 wakelock。flush 不等于 fsync，本次不承诺突然断电时的物理持久性。

闹钟替换依据：[Android AlarmManager 官方文档](https://developer.android.com/reference/android/app/AlarmManager)。

## 保留的隔离

没有合并 WORKER 与 UPLOAD_WORKER。SDK 的提交入口会取得与网络上传共用的锁；从采集工作线程直接调用可能被慢网络阻塞。初步尝试移除上传线程中转的改动已撤回，保留原隔离路径。

没有延长上传 8/30 秒窗口、修改睡眠入睡/清醒确认时间、删掉版本兼容 hook 或精简用户整夜排查所需的日志。

## 测试

30 项 debug 单元测试通过，debug APK 构建通过。新增 5 项资源回归测试覆盖：相同来源复用、来源变化/空值、日志逐行可见、重复初始化不重建写入器、跨天轮转、关闭后迟到写入、重新打开继续追加、三类闹钟反复设置不累积以及显式取消仍生效。

此前的睡眠测试跨天失败来自测试类读取宿主真实时间、被测类读取 Robolectric PAUSED 模拟时间的差异。现在测试数据使用同一模拟时间，固定初始时间由 setUp 设置；没有放宽生产代码的报告有效期检查。

本次只验证减少分配/文件打开/跨进程调用的行为，不将这些计数收益换算为未经真机测量的耗电百分比。
